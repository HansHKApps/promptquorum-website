How the layers fit together

Pick a runtime first — it decides what is possible. Everything above it is optional: a desktop app or web UI for chat, an IDE plugin for code, a RAG system for documents, an agent framework when one-shot calls stop being enough, image generation when you need visual output. Licence matters for commercial use: MIT and Apache 2.0 dominate; AGPL appears on a handful of UIs.

How this directory stays current

Reviewed every six months and patched between reviews. Projects inactive for two release cycles are removed. Founders can claim or correct their entry from the entry itself.

Frequently asked questions

What is the difference between a runtime and a desktop app?

A runtime (Ollama, llama.cpp, vLLM) loads model weights and serves an API. A desktop app is a chat UI that calls a runtime — some bundle one (LM Studio embeds llama.cpp), others need one installed (Open WebUI calls Ollama). The "How it runs models" filter above encodes exactly this.

Can I use several tools at the same time?

Yes — most stacks combine 2–4 tools against one Ollama instance: Open WebUI for chat, AnythingLLM for documents, Continue.dev for coding.

Which tools support Apple Silicon natively?

Ollama, llama.cpp, MLX-LM, LM Studio, Jan, GPT4All, Enchanted and most Electron/Tauri apps use the Metal backend. vLLM, TensorRT-LLM and ExLlamaV2 are NVIDIA-focused. Set "My machine: Apple Silicon" above to see unified-memory requirements.

Do all tools support GGUF?

GGUF is native to llama.cpp and everything that wraps it. vLLM and TensorRT-LLM use their own formats; MLX-LM uses MLX-converted weights. Use the "Works with — GGUF" filter.

Which tools are best with no coding experience?

GPT4All (simplest install), LM Studio (most features without a terminal), Jan (most privacy-conscious), AnythingLLM (easiest document chat).
